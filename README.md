# VisionBridge AWS MLOps

VisionBridge is an image question answering app based on the `mai-project` frontend. This `mlops-ese` branch deploys it on AWS with a reproducible DVC pipeline, Docker images, GitHub Actions, and a public HTTPS workspace.

**Live app:** [https://15-135-22-228.sslip.io/](https://15-135-22-228.sslip.io/)
**Deployment evidence:** [AWS deployment record](mlops/aws/DEPLOYMENT.md) · [five minute presentation](mlops/PRESENTATION.md) · [screenshots](ss/README.md)

## How it works

1. DVC tracks the demo images and BLIP model in a private Amazon S3 remote.
2. `dvc repro` prepares data, evaluates two BLIP checkpoints on the same small demo set, selects a champion, and records its hash.
3. GitHub Actions validates code, builds the BLIP API and MAI workspace Docker images, and publishes immutable Git SHA tags to GitHub Container Registry.
4. The EC2 runner pulls both images. The BLIP API fetches its selected model from S3; Ollama stores a lighter Qwen3-VL 2B model on the EC2 host.
5. Caddy serves the MAI workspace over HTTPS. CloudWatch receives inference logs, latency and error metrics, with error alarms.

All model inference and speech processing for the public app run on EC2 in the selected Region `ap-southeast-2`; the visitor's laptop only provides the browser, image, and optional microphone input. Qwen can take roughly 1–2 minutes per image question on this CPU instance. The private frozen Phase 4 OCR/gating bundle is not deployed, so reading answers are generated by Qwen without independently verified OCR boxes.

## Repository layout

| Path | Purpose |
|---|---|
| `mlops/` | DVC stages, model selection, API, cloud workspace adapter, AWS deployment scripts and evidence. |
| `visionbridge/`, `modules/`, `utils/`, `launch_workspace.py` | MAI frontend, cloud workspace, and retained research helpers. |
| Other root Python modules | Frozen MAI research files retained at their original paths for source hashes and local compatibility. |
| `scripts/` | Manual audits, benchmarks, validation and research commands; run with `python -m` from the repository root. |
| `tests/` | Maintained automated tests. CI selects the cloud and MLOps tests. |
| `docs/research/` | Older MAI methodology, training guides, reports and the full original local setup reference. |
| `notebooks/` | Historical training and evaluation notebooks kept for provenance. |
| `submission/`, `sample/`, `models/` | Evaluation provenance, attributed demo inputs, and model pointers/checkpoint files. |
| `ss/` | Dated screenshots for the course demonstration. |

The remaining root Python modules are intentionally retained where moving them would invalidate the frozen research bundle's source hashes or break historical local entry points. The separate BDA project and its VM files are not part of this branch.

## Reproduce and verify

Use Python 3.11 and the dependencies in [the MLOps guide](mlops/README.md). From the repository root:

```powershell
dvc pull
dvc repro
dvc metrics show
python -m unittest discover -s tests -p test_mlops_pipeline.py -v
python -m unittest discover -s tests -p test_cloud_workspace.py -v
```

The [CI workflow](.github/workflows/ci.yml) triggers on pushes to `mlops-ese`, validates the code, and publishes Docker images. After publishing succeeds, it calls the separate [CD workflow](.github/workflows/cd.yml) for EC2 deployment. The deployment script health checks the new services and attempts to restore the previous image if startup fails. The [latest verified deployment](https://github.com/Vkmstry1611/mai-project/actions/runs/40689647257) passed all three jobs before this cleanup and workflow split.

For the local MAI research workspace and private Phase 4 setup, read [the preserved original guide](docs/research/MAI_REFERENCE.md). That workflow has separate dependencies and assets. The public cloud deployment described here does not require them.

## Costs and limits

EC2, EBS storage, the public IPv4 address, S3 and CloudWatch consume AWS credits while provisioned. Check **AWS Settings → Billing** for the current credit balance. Stopping EC2 makes the public link unavailable; retained storage and the allocated IP can still incur charges. See [deployment and shutdown steps](mlops/aws/DEPLOYMENT.md).

The 13-question BLIP comparison is a pipeline demonstration, not a reliable accuracy estimate. Qwen has no official VizWiz score in this branch. See [result provenance](submission/RESULTS_AND_PROVENANCE.md) before citing research metrics.
